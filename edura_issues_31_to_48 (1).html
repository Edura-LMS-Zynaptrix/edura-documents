## User Story As the development team, we want to systematically verify every service against the OWASP Top 10 so that we can show the client and evaluators documented security evidence rather than assumptions. ## Background / Context - SRS Reference: NFR-006 (bcrypt), NFR-007 (OTP expiry), NFR-008 (no card data), BR-006 - SDS Reference: Section 7.1–7.6 (Security Design), Section 7.5 (Input Validation), Reference [6] OWASP ASVS 4.0 This is the feature-freeze day. The sweep checks the implemented system against the security design and fixes small gaps in place. Anything too large to fix is recorded honestly as a limitation in the report (#45). Passwords are handled by Asgardeo, so the bcrypt check only applies to any credential EDURA itself stores. ## Acceptance Criteria ### AC1: A01 Broken Access Control **Given** the FastAPI route tables of all 11 services **When** an automated test enumerates every POST/PUT/PATCH/DELETE route **Then** each one has a require_role dependency or is on an explicit allow-list (payment webhook, health, auth login/callback/otp); the test fails on any unlisted unprotected route ### AC2: A02 Cryptographic Failures and Secrets **Given** the three code repositories and their CI history **When** a secret scanner (gitleaks) runs **Then** zero findings are reported; JWTs are verified as RS256 against the Asgardeo JWKS; any local credential hashing uses bcrypt with work factor ≥ 12 ### AC3: A03 Injection **Given** all database access code **When** the sweep searches for text(), string-formatted SQL, and f-string queries **Then** every query goes through the SQLAlchemy ORM or bound parameters, and a negative test sending payloads such as ' OR 1=1-- to list endpoints returns 400/422 or empty results — never a 500 ### AC4: A05 Security Misconfiguration **Given** the staging environment **When** a request triggers an unhandled error in any service **Then** the response is a generic JSON error with no stack trace, debug is disabled, CORS only allows the staging frontend origin, and responses carry HSTS, X-Content-Type-Options, and a basic CSP header ### AC5: A06 Vulnerable Components **Given** the CI security stage (from #03) **When** pip-audit and npm audit run on develop **Then** zero HIGH or CRITICAL findings are reported; any accepted exception is listed with justification in the checklist ### AC6: A07 Authentication Failures **Given** the auth endpoints **When** the sweep sends repeated bad logins and more than 3 OTP requests in an hour **Then** Nginx rate limiting (100 req/min) applies, OTP generation is capped at 3 per hour per user (SDS 7.2.4), OTP expires at 5 minutes, and refresh token reuse returns 401 REFRESH_TOKEN_REUSE ### AC7: Evidence Checklist Produced **Given** AC1–AC6 are complete **When** results are compiled **Then** documents/security/owasp-checklist.pdf in edura-documents lists each OWASP category with PASS / FIXED / ACCEPTED-LIMITATION, the evidence (test name, command output, screenshot), and the commit that fixed it ## Technical Notes - Route audit test: shared/tests/test_route_protection.py — import each service's FastAPI app and walk app.routes - Tools: gitleaks, pip-audit, npm audit, optionally semgrep with the p/python and p/owasp-top-ten rulesets (run locally, no new CI stage required) - Security headers can be added at the Nginx / Ingress layer — coordinate with #39 so production matches - Not in scope for this sweep, and to be recorded as limitations if not implemented: mTLS between services, field-level AES-256-GCM encryption, virus scanning of uploads (all described in the SDS) - Do not add features today — fixes only (feature freeze) ## Test Requirements - [ ] Automated test: every mutating route is protected or allow-listed - [ ] Negative test: injection payloads never produce a 500 or leak data - [ ] Negative test: forced error returns no stack trace - [ ] Negative test: rate limit and OTP cap enforced - [ ] CI: gitleaks and audit tools report zero HIGH/CRITICAL ## Definition of Done - [ ] Route-protection test committed to edura-backend and passing in CI - [ ] All AC1–AC6 findings fixed or documented as accepted limitations - [ ] owasp-checklist.pdf committed to edura-documents/security/ (linked PR) - [ ] PR raised against develop;
