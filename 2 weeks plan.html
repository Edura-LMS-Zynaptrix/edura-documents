01 —

What This Plan Requires From Every Member

What will kill this plan

  • Any member going dark for even 1 full day
  • Debugging integration issues alone — always pair on cross-service problems
  • Polishing UI before core APIs are working
  • Trying to set up Azure AKS from scratch in Week 2 — configure it in Week 1 Day 3
  • Writing tests after features — tests and feature code in the same PR
  • Waiting for a perfect architecture — ship working code, refactor later
  • Feature creep — AI assistant, leaderboard gamification are Week 2 only if ahead

What will save this plan

  • AI generates the boilerplate — you review, integrate, and test
  • Each member owns 2–3 services end-to-end (schema → API → tests)
  • Shared Docker Compose running from Day 2 so everyone integrates daily
  • Staging deploy live from Day 5 — not Day 13
  • Daily 15-min sync: what's merged, what's blocked, who helps who
  • Feature freeze Day 10 — Days 11–14 are testing, fixes, and demo prep only
  • One person (Nadun) owns infra/CI full-time — never rotates off it
Architecture decision for speed: Run all 11 Python services as separate FastAPI apps inside a single edura-backend monorepo. Each service has its own folder, its own PostgreSQL Neon database branch, and its own Docker container — but they share one docker-compose.yml for local dev. This gives you the full microservices architecture your SDS specifies, while eliminating the overhead of 11 separate repositories. AKS deploys each service as a separate pod. Document this as ADR-08 in your documents repo.

  • PayHere HMAC webhook signature verification
  • Azure AKS deployment manifests and secrets config
  • Integration testing — seed data, cleanup, real assertions
  • Code review: every AI output reviewed before merge
  • Performance: Redis caching wiring, query optimization

Prompt pattern that works

  • "Generate a FastAPI service for [SVC] with these SQLAlchemy models: [paste schema]. Include router, CRUD, Pydantic schemas, health endpoint."
  • "Write pytest unit tests for this function using AAA pattern, mock Redis/DB: [paste function]"
  • "Generate Alembic migration for this ORM model: [paste model]"
  • "Write a RabbitMQ consumer in Python (pika) that listens to [event] and calls [function]"
  • Always paste your SDS section as context — AI output is better with constraints

Risk Register

Risk
Level
Mitigation
Asgardeo OAuth not working
CRITICAL
Test Asgardeo sandbox connection on Day 1 before writing any auth code. If Asgardeo has registration/config delays, fall back to custom JWT with bcrypt — document as ADR deviation. Do not lose more than 4 hours on this.
AKS deploy failing in Week 2
CRITICAL
Provision AKS on Day 3 (Week 1) and deploy a hello-world pod. If AKS is unresolvable by Day 10, use Railway + managed PostgreSQL as fallback — document in ADR. Production deploy on any platform beats no deploy.
PayHere webhooks not testable locally
HIGH
Use ngrok to expose local webhook endpoint for PayHere sandbox testing. In production, staging URL is already public. Write full mock-based unit tests so webhook logic is proven even without real PayHere calls.
RabbitMQ cross-service events not firing
HIGH
Test RabbitMQ publish/consume on Day 2 with a simple script before any service depends on it. Use the RabbitMQ management UI (port 15672) to inspect queues and messages during debugging.
Team member blocked for 1+ full day
HIGH
Each service owner pairs with a backup (see load table). If primary is blocked >4 hours, backup takes over. No single point of failure on any service.
CI pipeline flaky / slow
MEDIUM
Cache pip dependencies and Docker layers in GitHub Actions. If pipeline takes >8 min, skip integration tests on feature branches — only run on develop. Speed matters more than perfect coverage gating on feature branches.
Frontend integration with APIs broken
MEDIUM
Imansha builds frontend against staging URL from Day 5 — not localhost mocks. Real integration failures are caught in Week 1, not Week 2. Use FastAPI's auto-generated OpenAPI docs at /docs to verify endpoint contracts.
